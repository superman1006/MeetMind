MeetMind 冒烟测试说明
=====================

这份文档用大白话讲清楚：我们项目的冒烟测试都包含哪些文件、每一块到底测了什么。
所谓"冒烟测试"，就是一组跑得飞快、不依赖真实环境的自动化检查，每次改完代码跑一遍，
确认项目最核心的链路没被改崩——能不能编译、配置读不读得到、agent 路由对不对、
数据库 SQL 拼得对不对、前后端的收发逻辑还正不正常。它不追求覆盖每一个角落，
只保证"基本功能没冒烟（没起火）"。

怎么跑
------
在项目根目录执行 `pnpm test`，会同时把后端 runtime 和前端 desktop 两个包的测试都跑一遍。
用的是 vitest，全程纯内存、把数据库和 LLM 都用假对象（mock）顶替，所以不用起 Docker、
不用连 PostgreSQL、不用配 API key，两秒左右就能跑完。
目前一共 31 个测试文件、228 条用例，全部通过：后端 22 个文件 153 条，前端 9 个文件 75 条。


后端 runtime 测了什么
=====================

配置与常量
----------
config 目录下的 settings 和 constants 测试，确认应用启动时的"地基"是稳的：
配置对象能正确读出来而且是缓存单例（同一份不重复建），.env 里写的相对路径会被自动锚定成
绝对路径，数字字段会被正确转成 number。常量这边则确认 5 个角色（架构师在第一位）、
角色中文描述、以及"是不是合法 agent 名"的判断都没错。
另外 database/connection 下还单独测了表名拼接，确认每个 agent 的数据库表名是用受控前缀拼出来的。

Agent 的行为
------------
agents 目录的测试盯着 agent 回复的两个细节。一个是 coerceDone：模型有时把"是否结束"
返回成布尔、有时返回成 "true"/"yes"/"完成" 这类字符串，测试确认这些都能被正确地归一成真/假，
图不会因为格式不统一而卡死；顺带还测了把用户长期记忆拼进提示词的那段逻辑（没记忆就不加噪声）。
另一个是 streamStructured：确认流式输出时能一帧一帧地把新增的文字吐出来（打字机效果），
模型一次只吐一大段时也能正确退化处理。

图编排与路由
------------
graph 目录是整个多 agent 协作的"交通指挥"，测试最关键。route 测试覆盖了核心的路由判断：
达到迭代上限就强制结束（安全阀）、架构师宣布完成就结束、点名了合法角色就跳过去、
碰到非法或空的下一个角色就兜底回架构师——保证这张图永远不会卡死。
routePreprocess 则测前置的"分流决策"：闲聊/问答这类助手意图且置信分够高就走右侧回答助手，
分数不够或是开发需求/任务指令就一律走架构师团队（安全兜底）。
checkpointer 测的是断点续跑用的存档清理：能对三张存档表逐一删除，某张删失败也不会连累其它张。

数据库层
--------
database 目录的测试全部用假的数据库连接，只验证 SQL 拼得对不对、参数走没走占位符（防注入）。
chatStore 最全：建会话/消息两张表、新建会话、按用户拉列表、按时间倒序、读写消息、
重命名、删除、标记会话结束、以及崩溃续跑用的 pending_thread_id 列，每一条都确认发出去的 SQL 正确。
userStore 测注册用户（重名会被挡）、校验登录、读写用户的长期记忆。
splitters 测灌库前的文档切块：种子 JSON 原样透传不切，长文本按长度切成多段，
Markdown 按标题切，不同类型的文件各走各自的切块器，空白内容被跳过。

服务端 RPC 与推送
-----------------
server 目录测的是前端和后端之间那层接口。rpcServer 是最大的一块，把所有对外方法挨个测了一遍：
发消息、建/列/删/重命名会话、打断进行中的讨论、结束会话、切换模型、生成会话标题、
用户注册和读写记忆——每个方法都确认了正常返回、缺参数报错、会话忙时拒绝操作这几种情况。
runExecution 测一轮讨论真正跑起来时，模型吐出的帧怎么转成推送事件、新发言怎么落库、
个人记忆怎么注入。sseServer 那侧测的是服务器推送：事件能按会话广播给所有连接、
断开的连接不再收到。另外还有几个小而精的：titleSummary 测标题清洗（去换行、超长截断），
meetingSummary 测会议纪要的拼装，toolApprovals 测工具审批的挂起/兑现/取消，
sessions 测"会话忙不忙"这个标记位。

工具与通用函数
--------------
tools 目录测了网页抓取的 HTML 转纯文本（剥标签后不留大片空行）和 MCP 结果转文本。
utils 目录测的是几个到处都在用的基础函数：cleanBadChars 清理中文输入可能产生的坏字符
（孤立代理对 → 问号，合法 emoji 完整保留，防止下游 HTTP 序列化崩），
还有分隔线格式化、路径是否存在、角色配色，以及一组 CLI 打印函数的冒烟检查（能执行、不抛错）。


前端 desktop 测了什么
=====================

接口层
------
api 目录测前端怎么跟后端说话。rpcClient 确认请求按 JSON-RPC 信封发出、正常拿结果、
出错时抛对异常、请求 id 逐次递增。sseClient 确认订阅的是固定的事件流、收到各类事件能
正确解析并转交给对应处理函数、连接断开时的回调分支也对。

状态管理（stores）
------------------
stores 是前端的核心，测试也最密。chat 这个聊天状态测得最细：加用户气泡、开始一轮发言、
流式拼接文字、工具名去重累加、本轮结束清掉那个"建了但一个字没吐"的空占位泡（否则会一直转圈）、
加载历史、标记结束、错误提示、以及崩溃后断点续跑的整套状态流转，还有"尾部思考中"那个
转圈点到底什么时候该显示的规则。sessions 测会话列表的增删改查和切换选中。
auth 测注册和用户记忆的读写。ui 测侧边栏收缩、明暗主题切换与持久化、以及顶部 toast 提示的自动消失。

展示与工具
----------
markdown 测把模型输出的 Markdown 渲染成 HTML，重点是安全：正文里夹带的原始 HTML 标签会被
转义成纯文本而不是真标签，这是防 XSS 的第一道防线。sessionGroups 测会话列表按
今天/昨天/7天内/30天内/更早分组的逻辑（含本地自然日的边界切分）。
agentColors 测每个角色的配色和中文标签，未知角色有兜底。


一句话总结
==========
这套冒烟测试不碰真实数据库和真实大模型，纯靠 mock 在两秒内跑完，覆盖了从配置加载、
agent 路由、数据库 SQL、服务端接口到前端收发与展示的所有关键链路。
它的作用是：每次改完代码先跑一遍，只要全绿，就说明项目最核心的骨架没被改坏，可以放心继续。
