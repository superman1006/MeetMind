# MeetMind 数字人会议使用与恢复手册

## 启动

项目根目录是 `/Users/chenlv/Project/MeetMind`。运行需要 Node.js 20 或以上、pnpm、Docker，以及一个兼容 OpenAI 接口的模型。模型需支持工具调用和结构化输出。

首次启动时，在终端执行以下命令。先按根目录的 `.env.example` 配置 `.env`，填写 `API_KEY`、`BASE_URL`、`MODEL_NAME`。使用项目的 Docker Compose 时，数据库在宿主机的端口是 `5433`。

```bash
cd /Users/chenlv/Project/MeetMind
docker compose up -d
pnpm install
pnpm dev
```

等到后端显示 `3002` 已监听、Vite 显示 `5173` 已就绪后，浏览器打开 [http://localhost:5173](http://localhost:5173)。首次运行会准备索引并加载本地模型。日常启动时，数据库容器已运行即可直接执行 `pnpm dev`。

根目录 `package.json` 的 `dev` 同时启动两个工作区。只重启后端用 `pnpm dev:runtime`，命令转到 `apps/runtime/package.json` 的 `tsx src/index.ts`。只启动前端用 `pnpm dev:desktop`，命令转到 `apps/desktop/package.json` 的 `vite`。前端保存代码后会自动刷新。后端、角色密码或工具目录变化后需要重启 runtime。

## 账号与数字人

注册完成后，用该账号登录。左下角账号菜单的「设置」可以修改数字人名称、简介、个人记忆、可用工具及 Skills，并上传个人知识文件。支持 TXT、Markdown、JSON、PDF 和 DOCX，单文件上限 10 MiB。上传后列表展示文件名及文本块数。数字人在会议中使用自己启用的能力，会议中可见生成的回复和工具名称。

五个内置角色保留原提示词和知识库。想使用角色账号登录时，在根目录 `.env` 配置对应密码并重启后端。留空时仍可在会话中选择该角色。全局模型设置由 `admin` 管理。默认演示密码仅接受本机连接。在其他设备或部署环境使用管理员时，在 `.env` 设置 `MEETMIND_ADMIN_PASSWORD` 后重启后端。

| 内置角色 | 账号 | 密码配置 |
| --- | --- | --- |
| 架构师 | `architect` | `MEETMIND_ARCHITECT_PASSWORD` |
| 前端工程师 | `frontend` | `MEETMIND_FRONTEND_PASSWORD` |
| 后端工程师 | `backend` | `MEETMIND_BACKEND_PASSWORD` |
| 测试工程师 | `tester` | `MEETMIND_TESTER_PASSWORD` |
| 产品经理 | `pm` | `MEETMIND_PM_PASSWORD` |

项目搜索和读取工具限定在指定源码、文档及部署目录。写文件、编辑文件、读取进程列表和直接抓取 URL 仅在管理员主持且由其数字人调用时可用。工具目录会随运行时已加载的工具更新。飞书是后续接入项。

## 创建会议、发言与任务计划

1. 点击「+ 新会话」，填写会议名称并勾选参与的内置角色或注册用户。创建者为主持人，其他成员用自己的账号登录后可只读查看。
2. 主持人发送「你好，你是谁？」时，由主持人的数字人直接回复。右上角「任务计划」显示这一轮走直接回复。
3. 发送「每个人说一个 1」时，系统为主持人的数字人和选中的成员各排一个子任务。「任务计划」可查看当前轮次、历史轮次、执行顺序和已完成步骤。
4. 点击「打断」会停止当前执行，保留已保存的发言和计划。如果后端意外重启，重新打开会议后可选择「继续」或「放弃」。继续时从第一个未完成步骤开始。
5. 主持人可在左侧把会议归档。从「归档会话」重新打开，仍可查看历史消息、任务计划和纪要。

## 结束会议与生成纪要

会议空闲时，由主持人点击右下角「结束」。系统把会议状态更新为「已结束」，锁定发言，再把所有已保存的原始消息按顺序交给大模型整理。长会议分段处理，每段整理时会带入上一段的纪要草稿。生成失败时，主持人可以点顶部「重试纪要」。

默认输出目录为项目下的 [data/summary](../data/summary)。文件名格式为 `YYYY-MM-DD_HH-mm-ss_<sessionId>.md`，以会议创建时间开头。同一场会议使用固定文件名。正文第一行显示会议起止时间，使用 `Asia/Ho_Chi_Minh` 时区。参与者可从右上角「会议纪要」打开正文或下载 Markdown。

## 代码与数据定位

```text
Vue 会话界面 → JSON-RPC → 按会话成员构建 LangGraph
    START → rewrite_node → intent_node → task_boundary_node
        direct → 主持人的数字人 → teamRouter → END
        task   → task_plan_node → 数字人节点 → teamRouter
                                      ↑        │
                                      └── 下一步骤
```

- [meetingRpc.ts](../apps/runtime/src/server/meetingRpc.ts) 校验账号和会议角色，接收设置、会话、计划与确认操作。SSE 按会话成员分发，审批请求只发给主持人。
- [meetingGraph.ts](../apps/runtime/src/graph/meetingGraph.ts) 为每个实际参会的数字人注册节点。`teamRouter` 按数据库计划的顺序选下一节点，模型回复完成一个步骤后由系统推进。
- [meetingStore.ts](../apps/runtime/src/database/chat/meetingStore.ts) 中，`sessions` 保存主持人、参会名单、会议状态和归档时间。`meeting_rounds` 保存每条需求及轮次状态，`task_plans` 保存规划出的父任务和有序子任务。`messages` 保存逐条消息，轮次和步骤索引用来保证断点恢复时的幂等性。
- [meetingMinutes.ts](../apps/runtime/src/server/meetingMinutes.ts) 读取全量消息并生成文件。纪要任务的进度与文件名也保存在会话表中。

旧版五角色 CLI 在 `pnpm dev:cli` 下仍可使用。数字人会议和任务计划通过 Web 界面使用。Vite 及 Tauri 开发外壳共用这一套界面。

## 验证命令

在项目根目录执行 `pnpm typecheck`、`pnpm test` 和 `pnpm build`。还可以用两个账号复查新建会议、只读权限、直接回复、全员任务、恢复、归档与纪要生成。验收时使用隔离数据库及独立纪要目录，避免测试会话和文件混入日常数据。

本次验收使用隔离 PostgreSQL、真实模型及浏览器双账号。235 个自动化测试通过，前后端类型检查和构建通过。实测覆盖资料配置、知识上传和隔离、只读旁听、直接问答、全员任务、点名规划、断点恢复、归档及 Markdown 纪要。断点测试在首个步骤落库后停止后端，重启后并发提交恢复请求，只启动一次，已有回复没有重复。

本机切换时清理了 14 个旧测试会话、77 条关联消息和 6 份旧纪要。切换后保留 3 个原有账号，新增 5 个内置角色。已通过原来的前端地址登录并读取角色列表。
