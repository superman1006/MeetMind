## 一、会议纪要

## 会议纪要

用户要求复刻 GitHub 开源项目 [MeetMind](https://github.com/superman1006/MeetMind)——一个多 Agent RAG 协作系统。经四角色（PM、后端、前端、测试）依次拆解，形成完整交付方案并冻结。

### 关键结论与决策

- **里程碑排期**：7 周 / 35 人天，分三阶段交付。
  - M1（W1-2）：后端 DB 管线 + Agent 框架，前端脚手架 + 会话 CRUD，测试单测框架。
  - M2（W3-5）：RAG 检索 + Graph 编排 + SSE 流式，前端流式对话 + 中断 + 工具卡片，集成测试。
  - M3（W6-7）：知识库管理 UI，E2E + 压测，联调修复与部署文档。
- **PM 已拍板 4 项阻塞决策**：
  1. 中断行为：保留已流式内容。
  2. 工具调用展示：折叠卡片，可展开查看详情。
  3. 知识库上传：仅支持 txt / md / pdf，使用骨架屏。
  4. 空状态引导：问候语 + 3 个示例问题。
- **技术风险**：多 Agent 协作协议设计不确定性最大，W3 前必须完成技术 Spike 验证；CI 环境需预缓存 embedding/rerank 模型（~360MB）。

### 待办事项

- 各角色按冻结方案即日启动，PM 每周同步 M2 闭环进度并即时决策阻塞项。

## 二、各 Agent 的工作

### 架构师 (Architect / Tech Lead)

- 汇总四角色方案，冻结里程碑排期。
- 跟进 M2 闭环阶段技术风险（多 Agent 协作协议 Spike 结果）。
- 必要时协调前后端 SSE 事件契约冻结。

### 后端工程师 (Backend Engineer)

- W1 启动 DB 管线（pgvector + pg_trgm 混合检索 + cross-encoder rerank）。
- W3 前完成 Agent 编排引擎技术 Spike，输出接口草案。
- 按顺序交付：DB 管线 → RAG 检索 → Agent 层 → Graph 编排 → HTTP + SSE 服务。
- W5 前与前端冻结 SSE 事件格式（turn_start / delta / using_tools / turn_end / round_done）。
- 目标工时 14d，行覆盖率 ≥80%。

### 前端工程师 (Frontend Engineer)

- W1-2：搭建脚手架，实现会话 CRUD。
- W3-5：实现流式对话 UI、中断行为（保留已流式内容）、工具调用折叠卡片。
- W6-7：知识库管理界面（上传仅 txt/md/pdf，骨架屏）、空状态引导（问候语 + 3 示例问题）。
- W5 前冻结 SSE 消费方案与组件树。
- 目标工时 12d，关键路径覆盖率 100%。

### 测试工程师 (QA Engineer)

- M1（W1-2）：搭建 Jest 单测框架 + MSW mock，覆盖 Agent/RAG 核心单元测试。
- M2（W3-5）：SSE 事件契约集成测试、中断/重连异常场景、RAG 空结果降级。
- M3（W6-7）：Playwright E2E + k6 并发压测 + 安全扫描。
- 预置空/小/大三种规模知识库数据集；CI 预缓存 embedding/rerank 模型。
- LLM 非确定性场景使用语义相似度（>0.85）替代精确断言。
- 目标工时 9d。

### 产品经理 (Product Manager)

- 每周同步 M2 闭环进度，阻塞项即时决策。
- 按已拍板的 4 项决策（中断行为、工具卡片样式、上传类型、空状态引导）验收各阶段交付物。
- 维护用户故事验收标准，确保 M2 闭环不偏离 MVP 范围。
